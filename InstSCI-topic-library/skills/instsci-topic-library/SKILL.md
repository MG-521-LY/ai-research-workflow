# 主题文献助手：筛选与 InstSci 获取

把用户研究需求转成多来源候选、可追溯的筛选依据和经过核验的本地文献库。宿主 Agent 理解主题、扩展检索并阅读摘要；脚本负责去重、评审记录、目标名额和清单复核，获取全文使用已安装 InstSci。

## 运行入口

本技能脚本位于 `scripts/topic_library.py`，使用安装了 InstSci、PyMuPDF 的 Python 执行；Windows安装脚本也会生成 `instsci-topic` 命令。优先检查已有启动器或用户配置中的环境位置，勿使用不含这些依赖的系统 Python。CLI 参数与输入格式见 [任务协议](references/task-protocol.md)。

用户指定结果位置优先；否则在用户目录下 `.instsci/topics/<主题>-<日期>` 创建新任务。不要在上游源码中保存下载和私有证据。

## 从研究主题开始

1. 已有主题直接执行。用户明确给定篇数优先；未指定默认100篇。先简短说明“本次目标 N 篇”。生成互补检索式与纳入/排除条件，写入 `search-plan.json` 后通过 `init --plan` 保存。未指定年份就不自行限制近五年。
2. 优先使用 `search` 调用 InstSci 的 Semantic Scholar、OpenAlex、Crossref 检索，保留每个来源的请求状态。每组检索先收集适量结果，目标候选规模约为目标篇数的3倍。提供方报错或限流不能解释为没有相关文献。
3. 需要中文数据库题录时，使用用户有权限的知网/万方可见页面采集，标明 `portal` 后 `ingest`；InstSci 的通用 API 搜索不等同于知网主题检索。不得编造候选题名或摘要。
   用户选择本校图书馆入口时，可使用独立获取入口 `instsci library-papers`：配置真实学校官网/数据库导航，在同一可见浏览器里由用户或宿主 Agent 选库/检索，用户手动认证，接收并核验原生 PDF 下载。参见工作流 `docs/LIBRARY_PORTAL.md`。它不是本脚本 `acquire --route` 的新枚举，也不自动把主题候选标成成功；按实际清单与文件核对，再接 T004/分析入口。不要将配置机构、打开官网或页面跳转当已下载。
4. 对可能入选的候选补读实际摘要与关键词，再 `review` 写入 include/exclude、0—100相关性分、依据和具体理由。明确遵守用户的硬性条件，不能为凑篇数放宽。没有摘要时只能声明 title 依据，脚本上限70分；不能把关键词次数当语义筛选。
5. 默认按相关性排序；只有用户需要热度辅助时在初始化使用 `--heat-weight 0.2` 等权重。热度按同领域/类型/年份段和指标来源的当前样本比较，缺失值中性处理，不宣称学术质量或全库最热门。
6. 使用 `plan` 预约下一小批，再 `acquire --batch` 执行它提供的 InstSci 路线。默认逐篇推进，有助于精确计数、人工验证和中断恢复。无需用户重复批准已明确要求的检索与下载。
7. 每批后 `status`，普通失败后继续选择下一篇合格候选。目标只统计“仍符合当前筛选条件、原始清单验证成功、PDF当前可读且哈希未变”的不同内容。点击按钮、搜索条目数量或工具返回成功不算获取完成。
8. 合格候选不足时扩展仍符合原需求的检索；默认候选最多扩展到目标10倍，或连续两轮没有新增合格候选时结束并说明缺口。目标达到即停止，不额外多下。

## 继续、改数量与补位

- 同主题只说“30”表示总目标改成30；“再下20篇”表示当前有效成功数加20。分别使用 `set-target --count 30` 或 `set-target --add 20`。不要将年份、“近5年”等数字当篇数。
- 减小目标保留已有文件。若预约批次过大，先关闭未启动预约再重新规划；正在运行的下载需要检查实际进程和浏览器后处理。
- `status` 每次重读 InstSci 清单和文件；不手工把候选标成“已下载”。候选状态中的原 `pending` 是复用筛选代码的内部字段，不能用于获取计数。
- 重启后先看 `status`。已开始、未结束的批次不能再次 acquire。检查进程、浏览器、下载目录与清单，确认停止后通过 `close-batch --reason` 释放未决预约；清单损坏时先修复来源，不能重建空任务。
- `auth_required`、验证码/WAF、限额和配额台账异常会暂停整队列。必须完成对应人工操作或修复后，才能对具体候选 `retry --id --reason`。不要为了继续补位而直接清除阻塞。
- 失败不会自动无限重试。`retry` 仅许可该条再尝试一轮；仍须 plan/acquire。需要万方补充时可显式 `plan --route wanfang`，中文目标题名和第一作者仍须匹配。

## 获取与证据

执行获取前加载已安装的 `instsci` 技能和机构访问策略，遵守它的可见 CloakBrowser、机构选择、人工SSO/2FA/验证码、截图检查与下载限制。不要改用普通 HTTP 请求冒充出版社最终验证；不要把 DSH 既有 Chrome 登录状态当成 CloakBrowser 已授权。

本技能不接收密码，不处理验证码，不导出登录凭据。跨宿主同一任务一次只运行一个写入/获取流程。

## 交付与 Zotero

`export` 输出 `report.md`、`report.json`、`library.csv`、`zotero_manifest.json` 和 `zotero_handoff.json`。报告区分核验成功、普通失败、身份/验证码阻塞、清单异常、无合适候选和尚未跑完。

Zotero 清单只包含本次主题仍合格且核验成功的条目。用户要求入库且已配置连接时使用 InstSci 的 `zotero sync <任务目录>/zotero_manifest.json --attachment-mode linked_file`；成功数与入库数分别报告。没有 DOI 的中文记录需要已有 `zotero_item_key` 才能自动附加；缺少此映射据实列为待处理，不把生成交接清单说成已入库。
