# 架构、模块与数据契约

## 分层关系

工作流把资料获取与科研推断分开：InstSCI负责合法获取，T004负责资料与文库的衔接，T002/T003提供解析与检索基础，T005组织研究产物。T006是可选调度层，不代替这些模块的产物核验。

根目录 `workflow.py` 提供本地安装与使用入口：依赖检查、实际PDF去重/清单生成、只读完整性校验、T005结果快照以及自包含演练。`demo`直接调用T005真实解析/索引方法，停在模型问答之前；不会另造一套模拟科研流水线或改变原模块状态契约。

| 目录 | 输入 | 输出 / 作用 | 部署说明 |
| --- | --- | --- | --- |
| `InstSCI` | DOI、出版商、机构选择、已有权限 | 下载任务、文件、访问证据 | 保留上游可见浏览器要求 |
| `InstSCI-topic-library` | 主题、查询、摘要评审 | 主题任务、筛选与下载衔接 | 不将检索命中数当全文数 |
| `T001_zotero_ingest` | CSV / 导入材料 | 标准题录、入库映射 | 早期兼容入口，显式覆盖本机路径 |
| `T002_literature_analysis` | 本地PDF与清单 | 解析、方法卡、比较 | 独立模块含历史固定样本默认值 |
| `T003_paperqa_bridge` | 清单、配置、解析内容 | 原文片段与引用定位 | 原生问答需额外依赖 |
| `T004_download_zotero_bridge` | 下载任务 / 本地清单 | 核验台账、映射、统一清单 | 新任务优先默认工作流 |
| `T005_research_pipeline` | 统一清单、问题、模型配置 | 状态契约、比较、假设、报告 | 明确每主题独立输出目录 |
| `T006_dsh_mcp_control` | 授权会话、完整任务文档 | 受理回执、游标、运行状态 | 只面向正常本机DSH |

## 文件契约

- **原件**：用户合法取得的PDF，内容摘要用于去重和变更检测。
- **题录**：真实题名、作者、年份、DOI、版本；不从文件名猜测后直接当已核。
- **统一分析清单**：`instsci.unified_analysis_manifest.v1`；每项标记实际路径、身份与摘要。
- **入库映射**：关联真实Zotero父条目、附件与文件；未决项保持未决。
- **问答证据**：区分模型原始答案、解析结果、上下文与原文字符/物理页定位。
- **运行状态**：记录本次实际输入、阶段状态、缺口、失败原因与缓存依赖。
- **研究产物**：区分原文事实、AI推断、候选假说、待确认资源与待执行验证。
- **调度回执**：`request_id`绑定目标、内容指纹与模式；受理不是研究完成。

## 为什么不附运行环境和论文样本

虚拟环境、浏览器profile、DSH状态、真实文库和付费论文无法当作可公开复用源码一起打包。发布保留实现与配置模板，把这些本机资产留在原工作目录。历史回归脚本若依赖未随包分发的数据，不能计为新环境已通过的测试。

## 当前兼容性与已知限制

仓库包含逐步演进的脚本。本地文件处理优先 `workflow.py`；外部获取/文库主链推荐T004默认入口和T005显式参数。T001/T002、历史测试、部分T004兼容路径及Zotero专项脚本仍有原部署默认值。新环境先按帮助和教程配置，不直接执行历史一键脚本。

T006导出副本将项目根目录改成克隆目录/`AI_RESEARCH_ROOT`，授权会话清单默认空；历史建审查会话功能与真实集成测试需逐项检查，不在默认自检中执行。主工作目录没有因本次发布而被重构。
