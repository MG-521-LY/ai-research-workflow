# 使用入口与项目交付

2026-10-18：原定通用科研工具链范围已通过当前验收，进入实际使用与迭代。五篇、十篇和补充论文都是测试材料；新任务应使用自己的研究问题、清单和独立输出目录。

## 日常使用

1. **给出研究主题、问题和资料范围**。优先复用本地已下载资料；需要补充时使用既有InstSci主题检索、摘要评审和获取流程。涉及校园认证或验证码时按实际提示处理。
2. **核验并入Zotero**。默认沿用InstSci工作流；本地环境由桥接入口核对PDF、完整哈希、真实题录与父子附件，生成统一分析清单。重复资料复用已有条目。操作见[入口与恢复指南](deliveries/T004_download_zotero_bridge/instsci_default_workflow/README.md)。
3. **将清单和具体研究问题交给研究流水线**。使用每个主题独立的输出目录，默认PaperQA原生后端、Gemini本地代理gemini-3.8-flash-high；凭据引用现有本地配置。新任务、增量、换问题和强制刷新命令见[研究流水线使用指南](deliveries/T005_research_pipeline/USER_GUIDE.md)。
4. **先看状态，再看研究结论**。输出目录里的run_result.json说明completed/partial/failed、证据缺口；RESEARCH_SYNTHESIS_REPORT.md汇总证据卡、比较、候选、外检与方案。原文事实、AI推断、资源待确认项要分别审阅。非零退出和拒答不能当作完整成功。
5. **按同目录增量恢复**。正常重跑会检查缓存是否适用；补齐缺失资料或恢复网络后重跑。问题/模型/关键输入变动会使相关阶段失效；CLI用--no-resume强制刷新，默认续跑，不需要--resume参数。入口坏映射按recover指南阻断/核实，不能盲目重导入。

可直接给执行会话的任务描述：

> 使用既有InstSci文献入口和已签收T005流水线，围绕我指定的研究问题处理这批资料，单独建立本次输出目录。先复用已有PDF和Zotero，再补充必要资料；生成带来源与页码的证据卡、方法比较、候选假设、查重反驳、资源待确认清单和可证伪验证方案。默认3.8high，不静默换模型。逐项报告实际完成和缺口，保持原件与sources只读。
