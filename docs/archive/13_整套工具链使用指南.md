# 整套工具链使用指南

日期：2026-10-16。依据当前本地入口、项目分工及最近独立验收编写。本次只整理用法，没有启动下载、文库写入、模型调用或正式50篇分析。

## 一、用户怎样开始

用户提供资料位置、研究需求和必要的硬性条件；Codex整理研究任务、审查方向和交付，dsh执行具体程序、处理资料并保存产物。用户无需自己维护JSON或逐个运行内部模块。2026-10-16用户授权后，[DSH MCP桥接](deliveries/T006_dsh_mcp_control/README.md)已实际接通，Codex可直接向两个既有会话发送任务、读取执行状态并审核产物，无需继续手动复制。本轮正在完成授权十篇的真实入库与科研整链，完整结果仍须验收。

主流程：

已有PDF / 新检索下载 → 核对题录与文件 → Zotero及来源映射 → 分析清单 → 文献解析和证据问答 → 方法卡与跨篇比较 → 候选假设 → 补充检索与质疑 → 验证方案 → Codex审查 → 按证据迭代。

实验台架接入、自动调参和实验记录系统仍后置。现在可以形成验证方案，不把方案写成已完成实验。

## 二、两种文献入口

### 已有PDF：首次正式任务采用此入口

用户已有50篇推力分配论文，直接给出绝对目录，不重新下载。

dsh使用T004的本地入口扫描PDF，核对题录、DOI、已有Zotero映射、文件完整性和重复项；缺失或不能确认的题录进入待补清单。完成真实导入或核实已有条目后，生成用于研究的 `papers_manifest.json`，保留PDF与Zotero条目标识及哈希对应关系。

`scan-dir`负责扫描，`import-local`负责接入已有清单，实际提交由程序的 `--commit` 控制；默认扫描或生成材料不等于已经入库。这些参数由执行的Agent处理，不要求用户手工填写。原文件保留，工作产物使用独立目录。

用户可采用下面的任务表述，目录需替换为实际位置；这是使用模板，本轮没有执行：

> 使用“这里填写50篇论文的绝对目录”中已有的推力分配论文，建立一个独立研究任务。核对文件、题录、重复项和Zotero已有记录，补齐能证实的信息，不能确认的单列，不重新下载这批文件。围绕水下机器人推力分配，逐篇整理方法、假设、约束、工况、基线、指标和局限，完成跨篇比较、候选研究假设、补充检索与反例质疑、验证方案及带来源的报告。保留原文页码、代码来源和未解决问题；使用当前已验证的模型配置，在同一任务内连续执行，遇到问题修复后继续。原生PaperQA尚未完成时，承接第12号任务完成真实接入，如实标注未完成阶段。不要用测试样本替代正式资料，不启动硬件实验。

首次目标先了解方法分布和证据支持的缺口，不预先把某种算法或电机控制方法指定为创新答案。50是用户所述下载数量，实际有效篇数以核验为准。

### 需要补文献：使用主题采集入口

在具备本机技能和浏览器能力的Codex或dsh中，可自然语言调用已安装的 `instsci-topic-library`。例如：

> 使用 instsci-topic-library，为水下机器人推力分配中的执行器约束与故障处理补充20篇相关论文。阅读实际摘要后筛选，记录排除理由，优先获取与现有资料不重复的文献；缺失数量按合格候选补位，获取失败和需人工处理的项目如实列出。保存检索式、来源和文件核验结果；需要入库时先核对已有Zotero记录，报告下载数与真实入库数。

20篇和具体主题仅为用法示例，不是已确认的新增采集任务。中文知网题录可沿用原 `cnki-topic-library`；InstSCI通用搜索不等于知网库内检索。

InstSCI导出的 `zotero_manifest.json` / `zotero_handoff.json` 不等于T004的分析清单，也不等于真实入库完成。由执行Agent明确选用一个入库入口，核验后生成研究清单；不要让InstSCI同步和T004导入对同一批文献各执行一遍。本次尚未验证这项跨模块自动衔接。

## 三、各工具在使用中的位置

| 工具/模块 | 实际职责 | 用户主要查看什么 |
| --- | --- | --- |
| InstSCI主题增强 / 原知网技能 | 按主题收集候选、由Agent读摘要筛选并获取PDF | 检索范围、纳入理由、真实获取数、缺口 |
| T004 + Zotero | 文献入库、防重、来源核对及分析清单交接 | 有效文献数、待补题录、已入库与待核对项 |
| PaperQA2及研究流程 | 文献检索、带引用问答及后续分析 | 原文位置、覆盖情况、证据不足项 |
| dsh + 所选模型服务 | 执行程序、生成分析与报告、在使用中修复问题 | 运行产物、进展、失败与未完成项 |
| Codex | 明确问题、独立回查、审查比较和候选方向、维护记录 | 哪些结论可信、哪些还需补证据及下一步 |

DeepSeek或Gemini反代是可选计算后端。dsh聊天中可用，不等于PaperQA使用了同一服务；实际研究运行应记录生效的引擎、模型和检索设置。一次运行使用选定配置，不默认双模型全量重复运行。现阶段可复用稀疏检索，不以另购Embedding服务为前提。

## 四、一次研究应交付什么

1. 文献与来源清单：实际有效数量、重复项、题录缺口、Zotero对应及文件完整性。
2. 逐篇方法卡和比较矩阵：研究对象、数学模型、假设、约束、实验条件、评价指标、基线和局限；明确全文处理与检索命中的覆盖差别。
3. 候选假设卡：原文依据、与已有工作的差异、可检验预期、反例及失败判据；没有可靠缺口时可以不生成候选，不凑数或宣称全球首次。
4. 检索与质疑记录：查到的相关工作和代码，区分官方实现、第三方复现与工程参考。论文没有代码时记录缺失，不假定开源。
5. 验证方案、综合报告和未解决问题：先写基线、对照、指标及可行条件；实验环境尚未确认的条件留空或待确认。

先阅读报告、比较矩阵、候选卡及未解决清单，再由Codex抽查影响结论的公式、表值、实验条件和代码来源。候选需要补资料时再进入采集入口，证据不支持时修改或放弃，不只反复润色报告。
